# AI Agent 工具与技能业务闭环验证

本路线以**运行中应用的真实浏览器操作**为主验证。每个业务路径都要通过 AI 助手发起，按页面当前执行策略完成确认或直接执行，并在管理页面复查数据状态、助手最终答复和运行详情。自动化测试只能补充浏览器验证，不能代替它。

优先使用专用测试记录并在验证后清理。不要把真实用户、生产凭据或外部消息收件人当作测试数据。对无法安全回滚的外部副作用，应先验证提案和取消路径；真实发送仅在指定测试租户和收件人后执行。

## 自动化回归补充

修改 Agent 内置工具、技能管理、执行策略、确认流程或结果展示后，再从仓库根目录运行：

```sh
pnpm test:agent-workflows
```

该命令运行后端中覆盖工具注册、技能目录状态与资源读取、权限诊断、查询模板、操作确认、执行策略、结果回传和 IM 确认卡的固定回归集。测试使用本地数据库事务和临时技能目录，不会调用真实 IM 租户。

## 通用验证规则

每条业务路径都检查以下闭环：

1. **发现目标**：先使用对应查询工具列出或精确定位，不从相似名称猜目标。
2. **补齐参数**：缺少必填字段时只询问缺失字段；查询不得提前执行不完整操作。
3. **检查策略边界**：先按下方内置工具策略表核对可配置项和固定项。只有 `run_registered_query` 可切换策略；其他内置工具在界面中应禁用策略选择，服务端也必须保持固定策略。
4. **确认状态**：检查确认卡对应正确目标和变更；取消、过期、重复确认及权限或目标变化均不得执行操作。
5. **执行结果**：确认后检查持久化状态、审计记录、助手最终答复和运行详情；成功答复必须含业务结果，失败必须明确失败原因，不能只留下运行详情。
6. **权限与输出**：用允许和拒绝的用户各跑一次；确认密钥明文和哈希等凭证不会进入普通查询或日志。

## 运行详情与流式状态

在浏览器中验证工具调用和确认续跑时，同时观察 SSE 更新和页面时间线：

1. 使用有延迟的安全查询发起请求；工具未返回期间，运行详情应出现进行中状态和经过时间，收到完成/失败事件后更新同一条工具记录。不能只在最终答复后补写工具记录。
2. 让一次请求经过多次模型响应及多次工具调用；按事件顺序检查模型、工具和计划步骤，界面不显示轮次编号。运行详情应在同一助手回复中持续累积，页面刷新及后续追问时都应保留历史工具结果。
3. 让同一回复产生至少两个需要确认的工具提议；逐项确认或取消。前一项处理后仍有待处理项时不得先生成结论；全部处理后只汇总一次，且取消的操作不得重试或执行。
4. 有 `tool_execution_update` 的工具可以展示白名单进度；没有进度事件的工具只需显示调用状态与耗时，不应伪造内部步骤。运行详情超出固定高度时应在详情内部滚动，并在运行期间跟随最新事件。复杂多步请求可显示模型维护的计划；计划本身不能证明步骤已成功。

后端 SSE 状态事件的前端接收、完成态恢复和确认续跑应分别检查。自动化回归不能代替浏览器中观察真实流式状态。

## 内置工具执行策略范围

以工具配置接口返回的 `modeConfigurable`、`requiresConfirmation` 为准，并检查 UI 与运行时一致：

| 工具                                                                             | 策略                          | 验证要求                                                         |
| -------------------------------------------------------------------------------- | ----------------------------- | ---------------------------------------------------------------- |
| `run_registered_query`                                                           | 可配置：直接执行 / 确认后执行 | 两种模式各执行一次；确认模式在确认前不得查询，确认后只执行一次   |
| `diagnose_my_access`、`search_knowledge_catalog`、`search_knowledge`             | 固定直接执行                  | 策略控件禁用；提交相反策略后，接口和运行时仍保持直接执行         |
| `revoke_api_key`、`delete_api_key`、`system_management_change`、`create_api_key` | 固定确认                      | 策略控件禁用；提交直接执行后仍生成确认提案，确认前不得产生副作用 |

接口应仅将 `run_registered_query` 标记为 `modeConfigurable: true`；固定工具的客户端提交不能覆盖服务端策略。固定确认工具必须始终走现有确认卡片。

## 内置工具业务路径

| 工具                       | 固定业务路径                                                                | 必须看到的结果                                                                                                                                                     |
| -------------------------- | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `diagnose_my_access`       | 当前用户整体权限 → 指定权限检查 → 无权限用户拒绝访问                        | 只报告当前登录用户的权限，不把权限诊断误当成目标用户查询                                                                                                           |
| `run_registered_query`     | 逐个执行下方查询模板；缺参数时补齐；列表跨页直到找到目标或最后一页          | 固定模板结果、清楚的缺参提示、拒绝未知参数、审计记录不保存参数值                                                                                                   |
| `search_knowledge_catalog` | 输入问题 → 返回候选文档目录                                                 | 只给候选元数据，不把目录摘要当成正文证据                                                                                                                           |
| `search_knowledge`         | 先查目录 → 仅使用本轮返回的文档 ID 搜索正文 → 回答并附引用                  | 未查目录或使用目录外 ID 时失败；无相关正文时明确说明无法确认                                                                                                       |
| `revoke_api_key`           | 活跃 Key 列表/精确查询 → 提案 → 取消和确认各跑一次 → 查状态                 | 取消后仍活跃；确认后变为 revoked；结果明确指出目标                                                                                                                 |
| `delete_api_key`           | 吊销 Key 列表 → 精确查询 → 提案 → 取消和确认各跑一次 → 再查                 | 活跃 Key 被拒绝删除；取消后仍存在；确认后不存在；不能只查活跃列表来断言已吊销 Key 不存在                                                                           |
| `system_management_change` | 用户/角色查询 → 逐项执行创建、更新、启用、禁用、删除变更 → 取消/确认 → 重查 | 覆盖用户密码重置、用户状态/资料/删除、角色创建/更新/删除；保护内部用户、本人和最后管理员；结果包含明确目标和状态。密码重置仅在网页助手开放，以便一次性展示临时密码 |
| `create_api_key`           | 提案 → 取消和确认各跑一次 → 检查 API Key 列表和一次性凭证事件               | 取消不创建；确认后元数据可查，明文只通过网页助手的一次性安全卡展示；IM 不提供创建入口                                                                              |

### `run_registered_query` 模板覆盖

| 模板                            | 验证路径                                                                               |
| ------------------------------- | -------------------------------------------------------------------------------------- |
| `active_api_keys`               | 只列活跃 Key、分页、无 key 明文/hash                                                   |
| `revoked_api_keys`              | 只列已吊销 Key，作为删除候选，不返回密钥材料                                           |
| `api_key_profile`               | 以精确名称、ID 和别名查询活跃/吊销状态；不提供目标时提示补参；相似名称不能替代精确匹配 |
| `managed_users`                 | 分页列出用户；核对内部用户和敏感字段边界                                               |
| `managed_user_profile`          | 以 userId、精确邮箱或精确全名查询；同名时列出候选并要求按 ID 选择                      |
| `roles_with_permissions`        | 分页查看角色及权限关联                                                                 |
| `role_profile`                  | 通过 ID 或精确 code 查看角色详情                                                       |
| `permission_catalog`            | 分页查看已注册权限                                                                     |
| `permission_usage`              | 以权限 code 查询使用情况；无效 code 清楚报错                                           |
| `recent_audit_logs`             | 分页/过滤审计日志；不返回 IP、User-Agent 或原始 metadata                               |
| `recent_access_control_changes` | 分页查看权限变更；执行者字段按既有查询合同处理                                         |

## 技能管理路径

在隔离环境用 GitHub 仓库简称、GitHub URL 和 Git remote URL 安装技能，检查 CLI 将文件放入 `AI_AGENT_SKILLS_DIR/.agents/skills`，新技能默认停用；HTTPS ZIP、归档链接和本地路径应被拒绝。启用后确认新对话能列出并加载其 `SKILL.md`，停用后不能再加载。移除操作应通过 `skills remove` 更新 CLI lock 文件并删除目标技能；重启容器后已安装技能和启用状态应保留。验证路径遍历、符号链接越界和超出读取大小限制均被拒绝。

技能页面只提交 Git 来源；私有 Git 来源使用后端容器配置的 Git 凭据。通用回归不执行第三方技能脚本。脚本能力必须通过单独注册的工具接入并遵循权限与确认流程。

## 覆盖文件

固定命令包含以下现有测试套件：工具注册和策略、提示策略、权限诊断、全部注册查询、内置操作提案/确认/取消/过期、配置策略切换、知识检索、确认结果摘要、钉钉/飞书/企业微信卡片行为。

实时 LLM 质量和真实 IM 租户收发不属于本地自动回归；每次发布相关改动时还要按上面的隔离环境步骤验证对应集成。
