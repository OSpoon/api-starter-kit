# AI 助手能力

AI 助手是受后端治理、以工具为驱动的管理控制台助手。它根据项目知识、系统查询和权限诊断回答问题，并准备需要确认的管理变更；不会绕过权限、数据库和确认流程。

当前正式支持四种 UI 交付面和三个 IM Bot：管理台 Web、独立助手 Web、Tauri 桌面端、Chrome 扩展，以及企业微信、钉钉、飞书机器人。
它们共用同一套 backend Agent、知识库、注册查询、受控操作、身份绑定和权限校验；桌面端和 Chrome 扩展复用独立助手客户端实现，分别负责原生窗口与浏览器 side panel。
四种 UI 客户端支持通过文件选择或剪贴板发送单张图片，也支持图片加文字提问；企微、钉钉和飞书 Bot 仍按各自渠道表格中的输入形态工作。

### 如何理解这张表

- “支持”表示该入口可以调用同一套后端能力，不表示可以绕过权限。每次查询都会重新校验权限、参数、作用域和结果上限；每次管理变更都必须经过结构化确认。
- 外部机器人不会把自己的平台身份直接当作系统权限。只有完成 `channel + externalTenantId + externalUserId → system user` 绑定后，才可以访问系统能力。
- 群聊访客是例外：不绑定系统账号，只能检索公开知识库；访客会话按群和外部用户隔离，不能访问实时系统数据或发起管理变更。
- 企微、钉钉和飞书的差异不应在业务 service 中分别实现。新增 AI 能力时，应先注册到共享的工具、查询或动作 registry，再由各渠道适配器负责消息和卡片转换。
- 外部渠道更适合快速问答和确认操作；需要完整历史、较长结果、工具过程或连续管理任务时，优先使用管理台或独立助手客户端。查询达到 20 条后，所有入口都应引导用户打开对应管理模块查看完整分页数据。

## 支持范围

UI 助手接受 JPEG、PNG 或 WebP 图片，每条消息最多一张，文件大小不超过 2 MB；图片可以单独发送，也可以和文字一起发送。图片用于帮助 Agent 理解用户任务，任务明确时继续使用现有知识库或注册工具，并遵守原有权限和确认流程；不会默认只描述画面。所选聊天模型必须支持视觉输入。新会话首条图片消息会额外调用一次视觉模型，根据图片、用户文字和页面标题生成会话标题。

| 能力                 | 支持方式                                                                                                                               | 限制                                                                                                                         |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 项目、产品与流程问答 | `search_knowledge_catalog` → `search_knowledge` 两阶段检索                                                                             | 必须先检索权限过滤后的知识源目录，再限定 1 至 10 个文档检索正文；只使用正文摘录，目录元数据不是回答证据。                    |
| 权限诊断             | `diagnose_my_access`                                                                                                                   | 只针对当前登录用户。                                                                                                         |
| 实时系统查询         | `run_registered_query`                                                                                                                 | 只使用注册模板；固定最多 20 条；不支持自由 SQL、任意字段、分页或继续查询。更多数据请前往 API Key、用户、访问控制或审计模块。 |
| 管理变更             | 专用 Pi `AgentTool` + 确认 API；API Key 创建、吊销、删除分别使用专用工具                                                               | AI 只能生成提案，不能直接执行；确认时再次校验权限和目标状态。不同 API Key 操作彼此独立，避免模型混淆。                       |
| 多轮对话             | Pi Agent、完整消息历史、持久化滚动摘要、工具结果上下文和 pending query                                                                 | compaction 仅影响模型请求，不截断持久化历史；脱敏后的工具结果按 call ID 恢复，确认组全部处理后统一生成结论。                 |
| 复杂任务计划         | 模型通过 `update_task_plan` 发布和更新计划                                                                                             | 只用于展示复杂多步任务进度；计划步骤不能作为工具执行或业务操作成功的证据。                                                   |
| 可扩展技能           | 助手配置页调用 Vercel `skills` CLI 安装 GitHub 或 Git 仓库；助手按需读取已启用技能的说明和资源，并可运行声明 `Bash(node:*)` 的技能脚本 | 新技能默认停用；仅运行技能目录内的 JavaScript 文件，受服务端权限、超时和输出大小限制。                                       |

## 请求流程

```mermaid
flowchart TB
  A["用户消息"] --> B["保存用户消息"]
  B --> C["Pi Agent"]
  C --> D["知识源目录 / 注册查询 / 权限诊断"]
  D --> E["限定文档正文精检索"]
  E --> C
  C --> F["助手流式回复"]
  C --> G["变更提议"]
  G --> H["用户确认"]
  H --> I["后端复核并执行"]
```

查询结果达到 20 条后，助手不会继续请求下一批；应引导用户打开对应管理模块查看完整数据。业务模块自己的表格分页与 AI 助手查询协议相互独立。

管理台和独立助手会在回复下方流式展示可展开的运行详情，按事件顺序显示模型响应、工具状态和必要的执行计划，不显示轮次编号。需要用户确认的工具会先显示等待状态；一条回复有多个确认时逐项处理，在最后一项决策前不生成结论，之后基于保留的工具结果统一续答。长文本在运行详情中单行省略，悬停可查看受限摘要。详情会在固定高度内自动滚动，并在历史消息中保留；没有提供进度事件的工具只显示调用状态和耗时，不展示虚构的内部步骤。

## 安全边界

- 后端是认证、授权、参数校验、脱敏和审计的唯一权威。
- 模型永远不能生成或执行自由 SQL。
- 查询每次调用都重新校验模板、权限和参数，结果固定上限 20 条。
- 知识检索每次先校验 `knowledge:read` 并过滤角色范围；目录最多 12 个候选，正文最多选择 10 个目录结果。第二阶段不能使用其他轮次的文档 ID。
- LLM 元数据提取只返回 `summary`（界面显示为“知识源说明”）和 `topics`（界面显示为“可检索主题”）建议，保存前由管理员审核；旧的来源机构、文档类型、产品或业务对象字段已移除。
- 破坏性操作必须通过结构化确认卡，模型文本不是授权通道。
- 技能由管理员从可信来源安装；安装内容默认停用。已启用技能的说明和资源仍作为不可信输入处理，不能扩大权限或绕过现有工具契约；应用不提供任意 shell 执行。
- API Key、密码、token 和密钥值不会进入普通查询结果、聊天历史或日志。

## 配置与观测

模型、Embedding、ASR 和请求超时通过系统管理中的「LLM 配置」页面维护，保存后对下一次请求生效。Embedding 维度固定为 1024，不支持编辑；所选 Embedding 模型必须返回 1024 维向量。管理台 Web、独立助手 Web 和桌面端均支持语音输入：录音最长 60 秒、音频最大 10 MB，停止后先由配置的 `Qwen3-ASR-0.6B-4bit`（或自定义模型）转写，再将中文文本交给对话模型。上下文预算由模型的 `contextWindow`、输出上限和 Pi 的 token 估算共同控制；长会话由 Pi compaction 生成滚动摘要。

AI 请求运行状态由 Pi Agent、现有审计日志和对话消息记录维护。

评估命令：

```bash
pnpm --dir apps/backend exec node ace ai:evaluate
```
