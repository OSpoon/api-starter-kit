# AI 助手能力

AI 助手通过 backend 统一提供知识检索、注册查询和受控操作。管理端、独立 Web、桌面端和 Chrome 扩展共用 Agent runtime；网站可嵌入助手，另提供三个 IM Bot。所有入口均支持单张图片及图文提问。

## UI 客户端

| 入口         | 目录                       | 定位                            |
| ------------ | -------------------------- | ------------------------------- |
| 管理端 Web   | `apps/frontend`            | 系统管理页面中的浮动助手        |
| 独立助手 Web | `apps/assistant-web`       | 全屏对话工作区，可单独部署      |
| 桌面端       | `apps/assistant-desktop`   | 使用 Tauri 打包的独立助手客户端 |
| Chrome 扩展  | `apps/assistant-extension` | Chrome MV3 side panel           |
| 网站嵌入     | `apps/assistant-web`       | 通过 script 标签加载浮动助手    |

桌面端和扩展复用独立助手 Web 的界面和客户端逻辑。各入口的本地启动、构建和服务端配置见[工程开发指南](development.md)及[部署指南](deployment.md)。

网站嵌入使用 API Keys 管理页生成的标准 API Key。创建时即可复制 script 标签并粘贴到网站，接入方不需要编写额外客户端代码。同一把 Key 也可用于其他支持的 API 集成；嵌入后 Key 对访客可见，并拥有完整 AI 助手能力。不同浏览器会话的聊天记录彼此隔离，Key 可在管理端吊销。

## 管理台与渠道能力横向对比

企业微信、飞书和钉钉 Bot 通过渠道 adapter 接入共享 Agent。差异主要在身份绑定、消息呈现和平台配置。

| 能力               | 管理台与 UI 客户端             | IM Bot                                     |
| ------------------ | ------------------------------ | ------------------------------------------ |
| 知识问答           | 可用，受用户权限过滤           | 可用；未绑定的群聊访客仅能访问公开知识     |
| 权限诊断与系统查询 | 按当前登录用户权限执行         | 仅对已绑定且有权限的私聊用户开放           |
| 管理变更           | 生成提议，经界面确认后执行     | 生成提议，经渠道确认卡片后执行             |
| MCP 工具           | 支持                           | 不开放                                     |
| 图片提问           | 支持单张图片，可附加文字       | 依渠道接入能力解析图片并调用共享 Agent     |
| 会话管理           | 支持查看历史和继续处理待确认项 | 可通过 `/new` 开始当前渠道的新会话         |
| 消息呈现           | Web 使用流式对话和运行详情     | 使用渠道消息或交互卡片；表现因平台配置而异 |

渠道应用权限、卡片模板、身份绑定和排障见[渠道 Bot 参考](reference/ai-channel-bots.md)。

## 支持范围

- **知识问答：** 先搜索用户可访问的知识源，再检索所选文档正文；回答依据来自正文摘录。
- **权限诊断：** 仅检查当前认证用户的服务端权限。
- **系统查询：** 只运行已注册的查询模板，结果有固定上限；完整列表应在对应管理页面查看。
- **管理操作：** 通过结构化提议与确认流程执行，确认时再次检查权限和目标状态。
- **多轮对话：** 保存完整消息历史；模型上下文可压缩，工具和待补参数状态可跨轮恢复。
- **定时助手：** 管理端可用五段 CRON 创建任务；服务端 worker 以任务所有者权限运行只读助手，不开放写操作或确认流程。每次运行会保存记录，并按所选格式投递通用 JSON webhook 或企业微信群机器人文本消息。
- **MCP：** 管理员在 Agent 配置中添加 stdio 或 Streamable HTTP 服务，不单独配置执行策略。工具声明 `readOnlyHint: true` 时直接执行，其他调用需用户确认；IM Bot 不提供 MCP 工具。旧式 HTTP+SSE 不支持。
- **PDF 附件：** 在内置工具中开启「读取 PDF 附件」并通过弹窗配置 MinerU 后，用户可随消息附加一份不超过 5 MB 的 PDF，并明确授权外部解析。助手按需调用当前会话的附件读取工具。解析完成时会在当前回复中继续作答。等待超过当前轮次的解析时限时，可通过后续消息继续检查同一任务。
- **技能：** 聊天输入框输入 `@` 可按代码或名称筛选已启用技能；选择 `@<code>` 后发送，Agent 会先加载所选技能。管理员可从可信 Git 来源或单技能 ZIP（≤10 MB）安装技能。技能默认停用；启用后的脚本在 OS sandbox 中运行。格式和执行限制见[AI 助手架构](ai-assistant-architecture.md)与[部署指南](deployment.md)。
- **多模态：** Web 管理端、独立助手 Web 和桌面端支持语音输入；所有入口支持单张图片。图像模型和 ASR 需在服务端配置。

所有入口均受同一套权限和执行规则约束；Bot 平台身份须先绑定系统用户，群聊访客能力受限。

### 定时助手 Webhook

计划使用五段 CRON 表达式，按 backend 主机的系统默认时区计算。每次运行结束后，服务端向配置的 HTTPS 地址发送一次 `POST`。通用格式发送系统定义的 JSON 结果，并带有 `X-Automation-Run-Id`；企业微信格式发送文本消息，并以响应 JSON 中的 `errcode: 0` 判断投递成功。
有任务管理权限的用户可以在列表和编辑表单查看已保存的投递地址；仅有查看权限的用户不会收到该地址。

```json
{
  "event": "ai.automation.run.completed",
  "runId": 123,
  "automationId": 42,
  "automationName": "工作日摘要",
  "status": "completed",
  "scheduledFor": "2026-11-25T01:00:00.000Z",
  "startedAt": "2026-11-25T01:00:02.000Z",
  "completedAt": "2026-11-25T01:00:18.000Z",
  "summary": "运行结果文本",
  "error": null
}
```

失败运行使用 `ai.automation.run.failed`；网络错误或非 2xx 响应会记入运行记录，当前不会自动重试。

## 请求流程

```mermaid
flowchart TB
  A["用户消息"] --> B["backend 保存消息"]
  B --> C["共享 Agent"]
  C --> D["知识检索 / 注册查询 / 权限诊断"]
  D --> C
  C --> E["助手回复"]
  C --> F["变更提议"]
  F --> G["用户确认"]
  G --> H["backend 复核并执行"]
```

## 安全边界

AI 不执行自由 SQL 或任意 shell。数据读取使用注册模板；写操作通过确认 API。工具、查询、提议和权限实现见[AI 助手架构](ai-assistant-architecture.md)，通用安全约定见[安全与治理](security.md)。
